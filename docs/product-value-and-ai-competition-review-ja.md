# Web State Inspector の製品価値・AI時代の競合リスク評価

評価日: 2026-10-11  
位置づけ: 開発方針の検討メモ（外部利用者によるレビュー・市場調査結果ではない）

## 結論

Web State Inspector は継続する価値がある。ただし、AIによるブラウザ操作・CDP/Playwrightベースのデバッグとの競合リスクは高い。価値の中心を「AIにブラウザを操作させること」ではなく「人間が実際に遭遇した不具合の操作・状態・通信・例外を、後から調査できる証拠として残すこと」に置く。

特に、再現困難な不具合の記録と、膨大なイベントから原因調査に関連する文脈を抽出する用途に集中する。

## 評価（定性的な仮説）

| 観点 | 評価 | 根拠・留保 |
| --- | --- | --- |
| 技術的実用性 | 高い | Timeline / Network / Storage / Error の時間的な対応をまとめられる |
| AIによる代替リスク | 高め | CDP、Playwright、AIエージェントは同種の内部情報を取得可能 |
| 差別化 | 中程度 | イベント周辺の context copy は有用だが、他ツールでも実装し得る |
| 個人開発の継続価値 | あり | 限定的な目的に絞れば保守・検証しやすい |
| 一般消費者への普及 | 低め | DevToolsに慣れた開発者向けの製品 |
| 開発者向けニッチ需要 | あり得る | 利用者調査・導入実績による検証が必要 |

これは実測の評判やユーザー満足度を示すものではない。

## AIブラウザ操作との重複と違い

- AIブラウザ操作: ページを開く・クリックする・表示を確認する・場合によっては Console/Network/Storage を解析する。
- Web State Inspector: ユーザー本人による操作の最中に User Action / Route Change / Storage Change / Network / Error を記録し、時間的な文脈をまとめて渡す。
- 「AIにはブラウザ内部の情報が取れない」という差別化は誤り。アクセス手段と権限があればAIエージェント側でも取得できる。
- 真の差は、**AIに再現を依頼する前に起きた現象や、AI自身が再現しづらい問題の証拠をユーザーが残せること**。
- 記録したイベント間の時間的近接だけでは因果関係は証明されない。

## 現行実装で評価できる点

READMEに記載された以下の機能は方向性と合致している。

- User Action、SPA Route Change、Storage Change、Network、JavaScript/Console Error の統合Timeline
- 選択イベントの前5秒・後2秒を既定とする Copy event context
- 再現メモ・エラー・失敗通信・操作を優先するローカルAI Export
- 外部APIやAIサービスへの自動送信を行わない設計

## 主な課題

1. Chrome DevToolsのNetwork / Application / Consoleと部分的に機能が重複する。追加で拡張を入れる明確な理由が必要。
2. Start Recording以前のイベントは捕捉されないため、突発的な不具合を取りこぼし得る。
3. AI Exportは自動マスキングを行わない。Cookie、Authorization、token、request/response bodyなどの機密情報の流出に注意。業務利用における大きな障壁。
4. Framework Stateはアプリ側の明示的な診断ブリッジが必要で、任意のVue/Reactアプリの状態を無条件に取得できるわけではない。
5. 将来、AIエージェントが常時ブラウザイベントを観測するようになれば、現在の強みも統合され得る。

## 開発方針の優先順位

| 優先度 | 方針 | 具体例 |
| --- | --- | --- |
| 高 | 再現困難な不具合の記録 | 記録開始忘れへのUX改善、時系列の保存・比較は権限と機密性を検討して設計 |
| 高 | 関連イベントの抽出精度 | エラー直前の操作、Storage更新、失敗APIなどをノイズを抑えて抽出 |
| 高 | 機密情報対策 | 出力前プレビュー、機密キーのマスキング候補、共有前の明示的警告 |
| 中 | AI向け情報の圧縮 | トークン数削減、重複ログ集約、調査に必要な前後関係の保持 |
| 低 | AI自身によるブラウザ操作 | Playwright等との直接競合を避ける |
| 低 | 単純なStorage閲覧機能の拡充 | DevTools標準機能との差を生みにくい |

### 当面の実行案

1. 新機能を大量に加える前に、現行の「記録 → イベント選択 → context copy → AI分析」のワークフローを手元の不具合で複数回検証する。
2. 出力に含まれる機密情報の扱いを優先的に改善する。
3. DevTools単独での調査と比べ、調査時間・共有するログ量・再現に必要な情報の欠落を測る。
4. Chrome Web Store公開後は導入数だけでなく、継続利用や具体的な不具合調査の成功例を集めてから開発投資を判断する。
